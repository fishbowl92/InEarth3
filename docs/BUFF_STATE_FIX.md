# 버프 공동 해결 이력과 공개본 보정 기록 — 2026-09-07

## 실제 프로젝트와 공개본의 이력 구분

개발자가 당시 팀장과 대화한 뒤 확인한 회고에 따르면, 해당 버프 문제는 약 2년 전에 두 사람이 함께 해결했습니다. GitHub에는 그 해결 내용이 반영되기 전의 과거 코드가 올라와 있었습니다. 이번 검토에서 실제 프로젝트의 미해결 문제를 최초로 발견한 것으로 설명하지 않습니다.

2026-09-07 변경은 공개된 과거 코드에서 확인한 문제를 별도로 보정하고 검사한 작업입니다. 당시 공동 해결과 이번 공개본 보정은 서로 다른 작업입니다. 회사 관리 하의 최종 코드는 수집·열람·복제·공개 대상에 포함하지 않았으며, 당시 수정 코드와 이번 보정의 구현 방식이 같은지는 확인하지 않았습니다.

당시 해결 시점과 공동 작업 이력은 개발자의 회고에 근거합니다. 아래 코드 분석과 514개 검사 결과는 공개본 및 이번 보정에 한정하며, 당시 최종 코드의 구현이나 테스트 결과를 입증하는 자료가 아닙니다.

## 과거 공개본에서 확인한 문제와 이번 변경

| 위치 | 수정 전 문제 | 변경 이유와 내용 |
| --- | --- | --- |
| `removeBuffStateGab(int gab, buffState buffType)` | 활성화·조회는 열거형 번호에 1을 더한 비트를 쓰지만, 해제는 원래 번호의 비트를 사용 | 기존 저장 표현을 유지하면서 동일한 마스크로 해당 비트만 해제 |
| `manageBuff(buffState buffSort, int target, int kind = 0)` | 해제 함수에 실제 상태 `BuffState[target]` 대신 대상 번호 `target` 전달 | 해당 대상의 다른 버프를 보존하도록 실제 비트 상태 전달 |
| 같은 함수의 `kind == 2` | 중첩 수를 반환하는 순간 함수가 종료되어, 주석의 “반환 후 제거”가 실행되지 않음 | 삭제 전 수치를 보관하고 상태·목록·화면 참조를 처리한 뒤 기존 수치 반환 |

`removeBuffStateGab`에는 해제 위치를 명시하는 지역 변수 `mask`를 추가했습니다. 기존 임시 변수 `a`와 잘못된 마스크 계산은 제거했습니다. `manageBuff`에는 삭제 전 값을 보관하는 `removedCount`를 추가했습니다. 두 함수의 이름과 매개변수는 바꾸지 않았으며, 다른 게임 기능이나 버프 상태 저장 형식은 변경하지 않았습니다.

원본 `MapManager.cs`는 CP949(한국어 문자 인코딩)였으므로 편집 및 테스트를 위해 UTF-8로 변환했습니다. 변환 전후 한국어 주석과 코드 문자열이 동일함을 확인했습니다. 문자 인코딩 변환 때문에 원시 Git 차이에서는 주석 변경이 넓게 표시될 수 있지만, 기능 변경은 위 두 함수에 한정됩니다.

## 검증 방법과 결과

PowerShell 7이 설치된 환경에서 저장소 최상위 폴더를 열어 실행합니다.

```powershell
pwsh -NoProfile -File .\tools\Verify-BuffState.ps1
```

새 PowerShell 프로세스에서 `MapManager.cs`의 열거형과 실제 함수 5개를 읽고 C#으로 컴파일한 뒤 검사합니다. Unity의 벡터와 화면 참조는 최소 대역으로 대체하며, 버프 처리 구현을 테스트 파일에 복사해 두지 않습니다. 프로젝트 파일은 변경하지 않습니다.

- 수정 전: 첫 버프 `Atk`의 해제 검사에서 `Removal failed: Atk`로 실패했습니다.
- 수정 후: `PASS: 514 assertions, 20 buff types, 3 targets, 3 modes.`
- 20종 버프의 활성화·조회·해제, 반복 해제, 다른 버프 보존을 검사했습니다.
- 플레이어·골렘·몬스터의 세 대상에 대해 조회, 제거, 수치 반환 후 제거를 검사했습니다.
- 제거된 목록 항목과 화면 참조의 반환, 남은 항목 보존을 검사했습니다.

수정 전 파일을 별도로 준비했다면 `-MapManagerPath <수정_전_파일_경로>` 인자로 같은 검사를 실행할 수 있습니다. 이 인자는 검사할 파일만 바꿉니다.

## 검증의 한계와 남은 개선

이 테스트는 비트 상태와 목록 제거 흐름을 검사하는 제한된 회귀 테스트입니다. 전체 Unity 프로젝트와 씬·프리팹이 없어 게임 실행, 실제 화면 갱신, 전체 버프 획득·능력치 반영까지 검증한 것은 아닙니다. 성능 측정 결과도 아닙니다.

빈 `catch`로 예외를 삼키는 처리, 큰 관리자 클래스, 정수와 목록의 이중 상태 관리 문제는 이 공개본에 남아 있습니다. 이는 회사의 최종 코드에 대한 평가가 아닙니다. 향후 별도의 학습용 구현을 만든다면 순수 C# 버프 규칙과 화면 표시를 분리하고, 추가·중첩·해제 흐름을 검증하는 방향을 고려할 수 있습니다. 이를 위해 회사 코드를 가져오거나 최종본을 복원할 필요는 없습니다.
