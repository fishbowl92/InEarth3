# 개인 기여와 코드 확인 순서

[저장소 소개로 돌아가기](../README.md)

대표 개인 기여는 **버프 존재 여부를 비트 플래그로 분리하는 구조의 제안과 구현**입니다. 팀 프로젝트의 카드·덱·스킬 전체를 단독 구현한 것으로 표시하지 않습니다. 파일 전체의 소유권이나 기여율 대신 확인할 기능과 함수를 제시합니다.

## 문제와 선택

버프 종류별 상태 배열을 늘리는 방식을 검토하던 중, 존재 여부만 필요한 정보는 대상별 정수의 비트로 표현하고 실제 수치는 별도로 관리하는 구조를 제안했습니다.

- `BuffState`: 플레이어·골렘·몬스터에게 어떤 버프가 있는지를 표현합니다.
- `buffListNew`: 버프 종류, 실제 수치, 화면 참조와 관련 스킬 정보를 보관합니다.
- 같은 버프를 추가하면 목록의 기존 수치에 합산하고, 해제 시 상태와 목록을 함께 정리합니다.

모든 버프 데이터를 정수 하나에 압축한 것은 아닙니다. 정수의 비트 수에는 한계가 있고 목록 검색 비용도 남습니다. 당시 메모리 사용량이나 처리 속도를 측정한 자료가 없으므로 성능 개선율을 주장하지 않습니다.

## 남아 있는 한계

공개본은 비트 상태와 목록을 별도로 유지하므로 두 구조의 일관성 관리가 필요합니다. 빈 예외 처리와 관리자 클래스의 큰 책임도 공개본에 남아 있습니다. 이는 회사 최종 코드의 상태를 평가한 내용이 아닙니다. 이번 검증은 일부 순수 처리 흐름을 대상으로 하며, 전체 Unity 게임 실행이나 화면·능력치 반영까지 검증한 것은 아닙니다.
